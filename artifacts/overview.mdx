An artifact is a designed, rendered piece of work: a slide deck, a moodboard, a diagram, an interactive prototype, a dashboard, a print-ready document. Every artifact is made of frames — the slides, pages, or panels of the work — laid out on a canvas.

## Artifact types

There are four kinds of artifact. The type decides the frame size and how the work is shown.

| Type | For | A blank one starts with | When you show it |
| --- | --- | --- | --- |
| **Presentation** | Slide decks — fixed-size slides the viewer steps through | Two 1920×1080 slides | Steps through one slide at a time |
| **Artboard** | Free-form canvases — graphics, boards, and diagrams | One 1440×900 frame | Opens fitted, and you pan and zoom around it |
| **App** | Interactive apps, prototypes, and dashboards | One frame that fills the screen | Runs edge to edge |
| **Publication** | Designed, paginated documents — print-ready pages | One letter-size (816×1056) page | Scrolls continuously, like a PDF |

## Creating an artifact

The main way to create an artifact is to ask the agent.

<Steps>
<Step title="Describe what you want">
In the chat panel, tell the agent what to make — "Create a five-slide deck summarizing the Q3 review" or "Build a one-page poster for the launch event." If the request leaves too much open, the agent asks a few questions first: what it's about, who it's for, what material to draw from.
</Step>
<Step title="Watch it build">
The agent builds the artifact frame by frame, and the chat shows its progress as each frame is added.
</Step>
<Step title="Open the result">
When it's done, the artifact appears as a chip in the chat. Click it to open the artifact.
</Step>
</Steps>

You can also start from a blank one: click **New** in the top bar, choose **More types…**, and pick **Presentation**, **Artboard**, **App**, or **Publication**. A blank artifact offers three example prompts suited to its type — for a presentation, "Build a pitch deck for a client: the problem, our approach, the team, the ask". Click one to send it to the agent, or describe what you want in the chat.

On Studiograph Cloud, the **Getting Started** folder holds example presentations, publications, diagrams, infographics, landing pages, and social media posts to start from.

## Working on the canvas

Opening an artifact shows all of its frames on a canvas. Pan with the trackpad and pinch to zoom, or use the zoom controls. The canvas toolbar sets what a click does:

| Tool | Key | What it does |
| --- | --- | --- |
| **Select** | <kbd>V</kbd> | Click a frame, or an element inside one, to select it |
| **Pan** | <kbd>H</kbd>, or hold <kbd>Space</kbd> | Drag to move around the canvas |
| **Interact** | <kbd>I</kbd> | Clicks go to the artifact itself — use it to try out a prototype or app |
| **Marquee select** | <kbd>M</kbd> | Drag a rectangle around an area |
| **Lasso select** | <kbd>Q</kbd> | Draw around an area freehand |

**Reset view** fits everything back on screen, and <kbd>Esc</kbd> clears the selection.

### Editing with the agent

Most changes are a request to the agent. To point at a specific part, select a frame or an element — or draw a marquee or lasso around an area — then say what to change: "make this headline bigger," "swap this chart to a bar chart." The agent knows what you selected and edits that part.

### Editing directly

A few edits you can make yourself:

- **Edit text** — double-click a text element, or select it and press <kbd>Enter</kbd>. Press <kbd>Esc</kbd> when you're done.
- **Delete** — select frames or elements and press <kbd>Delete</kbd> or <kbd>Backspace</kbd>. Studiograph asks you to confirm.
- **Reorder frames** — drag a frame's label.
- **Rename a frame** — double-click its label.

There's no drawing tool; for anything new, ask the agent.

### Working together

When teammates have the same artifact open, you see their cursors and selections live, and a **Chat** button (<kbd>/</kbd>) lets you talk right on the canvas. The **Comments** panel holds comments on the artifact as a whole, and the **History** panel previews earlier versions — choose **Restore** to bring one back. The current version stays in History, so restoring never loses work.

## Showing an artifact

Click **Show** in the artifact's toolbar to open it in a new browser tab, without the rest of the app. How it behaves depends on the [type](#artifact-types). A presentation steps one slide at a time:

| Key | Action |
| --- | --- |
| <kbd>→</kbd>, <kbd>Space</kbd>, or <kbd>Page Down</kbd> | Next slide |
| <kbd>←</kbd> or <kbd>Page Up</kbd> | Previous slide |
| <kbd>Home</kbd> or <kbd>R</kbd> | Back to the first slide |
| <kbd>End</kbd> | Last slide |

On a phone, pinch to zoom and drag to pan around an artboard.

## Sharing

Open the **…** menu and choose **Share**. **Create public link** makes a read-only link anyone can open, and copies it for you. The public page opens the artifact the way **Show** does, and it updates automatically every time the artifact is saved. **Stop sharing** turns the link off. See [Sharing](/workspace/sharing#public-share-links).

## Downloading

Open the **…** menu and choose **Download**:

| Option | What you get |
| --- | --- |
| **PDF** | One page per frame — or, for a publication, one page per laid-out page |
| **PNG** | One image per frame. An artifact with several frames downloads as a zip. |
| **HTML** | A self-contained HTML file that works offline, with fonts and libraries built in. If the artifact uses files from your library, you get a zip with the page and an `assets` folder. [Live data](/artifacts/live-data) doesn't load in the HTML version. |
| **Markdown (.md)** | The artifact's source file |

One download runs at a time. There is no PowerPoint export.

## Fonts

Artifacts get fonts two ways:

- **Your library, for brand fonts.** Upload licensed or custom font files (`woff2`, `woff`, `ttf`, `otf`) to your [library](/library/media-in-your-work) and the agent can apply them by family name. When you ask for work carrying a brand's name, the agent checks your library for that brand's fonts first, and if they aren't there yet, it uses a close substitute and tells you, so you can upload the real ones. Fonts in the artifact's own folder, or in a folder shared with everyone, render for viewers automatically and are bundled into downloads. If you'll move the artifact to another top-level folder, see [What moves with an entry](/workspace/entries#what-moves-with-an-entry).
- **Google Fonts, by link.** A standard Google Fonts stylesheet link (`fonts.googleapis.com`) just works — ask the agent for any Google font by name. Downloads embed the font files, so a PDF or HTML file keeps the exact typeface, even offline.

Other external font hosts aren't supported — import the files into your library instead.

## Libraries and external resources

Artifacts run in a locked-down sandbox, with a small, pinned set of trusted sources allowed in:

- **Built-in libraries** — three.js (3D), D3 (data visualization), Motion (animation), and p5.js (generative and creative coding). The agent requests them per artifact, and Studiograph serves verified copies from your workspace's own server, so no third party is involved when someone views your work.
- **Other JavaScript libraries** — the agent can use any library published on `cdnjs.cloudflare.com` or jsDelivr's npm mirror (`cdn.jsdelivr.net/npm/…`), always pinned to an exact version so your artifact never changes behavior when a library updates. HTML downloads include these too.
- **Everything else stays out.** Arbitrary external scripts, images, trackers, and network calls are blocked by the sandbox. For an image or file hosted elsewhere, import it into your library — or ask the agent to save it from its web address.

## When something doesn't show

| Message | What it means |
| --- | --- |
| **Artifact body could not be rendered.** | Ask the agent to recreate the artifact. |
| **A file couldn't load** | The artifact uses a file that was deleted, or that you don't have access to. |
| **No access to this data** | The artifact reads a dataset you can't see. See [Live data](/artifacts/live-data#who-sees-the-data). |
