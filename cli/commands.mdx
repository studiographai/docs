## Getting started

### `init`

Create a new workspace.

```bash
studiograph init <team-name> [directory]
```

| Argument | Description |
|---|---|
| `team-name` | Display name for your team (e.g. "Acme Studios") |
| `directory` | Directory to create (defaults to slugified team name; use `.` for current dir) |

| Option | Description |
|---|---|
| `--demo` | Scaffold the `meridian-rebrand` example project |
| `--github` | Provision matching GitHub repos as part of init |
| `--github-org <org>` | Use this GitHub org when creating repos |

Without `--demo`, `init` creates a bare workspace and the interview agent drives onboarding from the chat panel.

### `join`

Join an existing workspace by connecting to a running server.

```bash
studiograph join <server-url> [directory]
```

Prompts for email and password, fetches the workspace metadata, and clones every folder you have access to via the embedded Git HTTP server. Admins additionally receive sources, connector configs, and `ABOUT.md` via the config bundle endpoint.

### `clone`

Clone an entire workspace with full admin setup — includes LLM and connector configuration.

```bash
studiograph clone <server-url> [directory]
```

## Daily workflow

### `start`

Launch the interactive agent chat in the terminal.

```bash
studiograph start [--verbose]
```

### `pull`

Pull latest changes across all folders.

```bash
studiograph pull [--remote <url>] [--data] [--api-key <key>]
```

Without `--remote`, runs `git pull` against each folder's existing remote. With `--remote <url>`, pulls workspace config (auth seed, workspace.json, ABOUT.md, sources, connectors) from the API. Add `--data` to also pull folder markdown via the embedded Git HTTP server.

### `push`

Push local commits across folders.

```bash
studiograph push [folder] [--remote <url>] [--data] [--api-key <key>]
```

Without `--remote`, runs `git push` against each folder's existing remote. With a server set in `workspace.json` (via `studiograph join`), it pushes via the embedded Git HTTP server, creating the folder server-side if needed.

The `--remote <url> --data` form pushes both config and all non-personal folder markdown to the named server. Personal folders are always skipped.

### `commit`

Git commit entity changes across all folders.

```bash
studiograph commit [--message <prefix>] [--config]
```

| Option | Description |
|---|---|
| `--message` | Commit message prefix (default: `update`) |
| `--config` | Also commit `.studiograph/` changes |

`commit` calls `reconcileRepos()` first — adds folders that exist on disk but aren't registered, removes entries for deleted folders.

## Data sync

### `sync`

Pull new entities from configured sources.

```bash
studiograph sync <folder>
```

### `sync refresh`

Refresh a single entity from its source.

```bash
studiograph sync refresh <entity-id> [-c <folder>] [-y]
```

Refresh updates only source-mapped fields — user-added fields and custom body content are never overwritten.

### `sync status`

Show sync configuration and last sync time.

```bash
studiograph sync status [folder]
```

### `sync source`

Manage source definitions.

```bash
studiograph sync source list
studiograph sync source add <name>
studiograph sync source remove <name>
```

## Workspace management

### `about`

Display or edit workspace identity (`ABOUT.md`).

```bash
studiograph about [-e] [-i] [-s <file>]
```

| Option | Description |
|---|---|
| `-e, --edit` | Open in `$EDITOR` |
| `-i, --interactive` | Step through sections interactively |
| `-s, --set <file>` | Set from file |

### `folder`

Manage folders.

```bash
studiograph folder add <name> [-d <desc>] [--graph-type project|function|shared-resource]
studiograph folder list
studiograph folder rename <old> <new>
studiograph folder remove <name>
```

### `index`

Build search index (full-text and optional semantic search).

```bash
studiograph index [--repo <name>]
```

### `lint`

Check entity completeness against schemas.

```bash
studiograph lint [--fix]
```

### `orphans`

Find entities with zero inbound references.

```bash
studiograph orphans [--entity-types <types>] [--min-age <days>] [--repos <repos>] [--tombstone] [--delete] [--dry-run]
```

### `config`

Manage user configuration (`~/.studiograph/user.json`).

```bash
studiograph config                  # Interactive menu
studiograph config set <key> <val>  # Set value
studiograph config get <key>        # Get value
studiograph config list             # Show all
```

Supported keys: `model_provider`, `model_id`, `api_key`, `voyage_api_key`, `vector_db_path`, `enrichment_model_id`.

## Server and deployment

### `serve`

Start the HTTP server (Graph API, chat, WebSocket, embedded Git, MCP, webhooks).

```bash
studiograph serve [-p <port>] [-H <host>] [--verbose]
```

Default port: `8000`. Honors `PORT` and `HOST` environment variables. Run **from inside the workspace directory** — the server uses `process.cwd()` as the workspace root.

### `user`

Manage user accounts.

```bash
studiograph user add <email> [--name <n>] [--password <p>] [--role admin|member]
studiograph user list
studiograph user remove <email>
```

`user add` provisions the user's personal **My Entries** folder automatically. The first user created becomes the workspace owner.

### `deploy railway`

Deploy the workspace to Railway.

```bash
studiograph deploy railway [-n <name>]
```

The wizard prompts for Railway credentials, sets required environment variables, and pushes config + data to the new deployment. Credentials are saved to `~/.studiograph/user.json`.

### `redeploy`

Trigger redeployment of an existing Railway service. Updates the start command to the exact npm version (e.g. `npx --yes studiograph@1.3.3-next.11 serve`) to bypass tag caching, and sets a `DEPLOY_TS` env var to force a fresh build.

```bash
studiograph redeploy [project]
```

## Integrations

### `mcp`

Start the stdio MCP server for AI tool integrations.

```bash
studiograph mcp [workspace]
```

See [MCP integration](/cli/mcp) for client configuration.

### `connector`

Manage external MCP connectors. Connectors give the agent access to remote services (Linear, Asana, Slack, Granola, etc.).

```bash
studiograph connector add <name> [--url <url>] [--command <cmd>] [--args <args...>]
studiograph connector list
studiograph connector remove <name>
```

For named connectors (`slack`, `linear`, `granola`, `asana`, `figma`), `add` runs an interactive setup wizard. Custom MCP servers can also be added by pasting a JSON config block in **Settings → Connectors → External Connectors**.

### `r2`

Manage Cloudflare R2 asset storage.

```bash
studiograph r2 setup                          # Configure bucket
studiograph r2 upload <dir> [--prefix <p>]    # Upload directory
studiograph r2 sync                           # Upload and rewrite asset URLs
```

## Maintenance

### `reset`

Reset workspace by removing all entity data (keeps configuration).

```bash
studiograph reset [--yes] [--keep-sync-state]
```

### `clear`

Clear agent sessions, memory, or both.

```bash
studiograph clear [sessions|memory|all]
```

### `update`

Check for and install the latest version.

```bash
studiograph update [--check] [--force]
```
