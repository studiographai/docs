## Overview

A **workspace** is the root of your Studiograph knowledge graph. It contains [folders](/concepts/folders), configuration, authentication state, and installed apps. A workspace maps to a directory on disk, with each folder backed by its own Git repository.

## Structure

```
my-workspace/
├── .studiograph/                # Workspace config and state
│   ├── workspace.json           # Settings, folders, schema extensions, sync rules
│   ├── ABOUT.md                 # Workspace identity (vision, mission, profile)
│   ├── auth-seed.json           # Portable users + JWT secret + workspace API key
│   ├── auth.db                  # SQLite — users, sessions, folder access (gitignored)
│   ├── api-keys                 # Workspace API key plaintext (gitignored, mode 0600)
│   ├── pending-commits.json     # Idle-batched edits awaiting commit (gitignored)
│   ├── commit-audit.jsonl       # Append-only audit of system-driven commits
│   ├── connectors/              # Sanitized MCP connector configs (committed)
│   ├── sources/                 # Sync source definitions (committed)
│   ├── apps/                    # Installed app plugins (committed)
│   ├── search/                  # LanceDB index (gitignored)
│   ├── yjs/                     # Collaborative editing state
│   └── migrations.json          # Applied schema migrations
├── meridian-rebrand/            # A folder (Git repo)
│   ├── project/
│   │   └── meridian-rebrand.md
│   └── meeting/
│       └── kickoff-2026-01-15.md
├── clients/                     # Another folder
│   └── organization/
│       └── meridian-health.md
└── entries-{userId}/            # Personal "My Entries" folder (gitignored)
    └── note/
        └── inbox-2026-04-26.md
```

## Configuration

Workspace settings live in `.studiograph/workspace.json` and define:

- Workspace `name` and identity
- Registered folders (each with `name`, `graph_type`, optional `description`, `sync` rules, `personal` flag)
- `schema_extensions` for additive fields or custom entity types
- App configuration
- `server_url` / `railway` fields (set by `studiograph join` or `deploy`)
- Optional `enrichment_model_id` for background tasks (insights, capture)

## Workspace identity (ABOUT.md)

The `.studiograph/ABOUT.md` file is your team's profile — vision, mission, capabilities, values, anything you want the agent to know about you. The built-in interview agent synthesizes it from graph entities after onboarding, and the agent uses this context to tailor every response.

Edit it via `studiograph about` (with `--edit`, `--interactive`, or `--set <file>`), via the **Settings → Organization** modal, or by asking the agent to update it.

## Authentication state

Studiograph is multi-user. Authentication runs locally inside the workspace, backed by SQLite — there's no external auth service.

- `auth.db` — SQLite database with `users`, `folder_access`, `api_tokens`, and OAuth tokens. Gitignored; rebuilt from `auth-seed.json` on first boot.
- `auth-seed.json` — portable users (with bcrypt hashes), workspace API key, JWT secret, and `folder_access` grants. Committed to the config repo so deployments stay in sync. Auto-exported after every user/access change.
- `api-keys` — plaintext workspace API key, mode `0600`, gitignored. The key itself rides in `auth-seed.json`.

See [Authentication & access](/concepts/access) for the full model.

## Personal folders

Each user gets a `entries-{userId}` folder on account creation, displayed as **My Entries**. Personal folders live alongside team folders in the workspace directory but are gitignored from the team's git workspace and skipped by `studiograph push --remote --data`. They can be shared with teammates without losing the `personal: true` flag.

## User configuration

Per-user settings live at `~/.studiograph/user.json` (mode `0600`):

- LLM provider and model preferences
- Provider API keys (Anthropic, OpenAI, Google, xAI, Groq, OpenRouter)
- Voyage AI key (optional, enables semantic search)
- Vector database path
- Railway deployment IDs and R2 secrets

Other home-directory state:

- `~/.studiograph/auth.json` — GitHub OAuth token (for `studiograph init --github`)
- `~/.studiograph/connectors/<name>.json` — full connector configs with literal secrets (mode `0600`)
- `~/.studiograph/sessions/{userId}/` — chat session history (server-side, scoped per user)
- `~/.studiograph/memory/{userId}/` — agent memory files

Workspace config layers under user config, which layers under environment variables for resolution of API keys, R2 credentials, and similar secrets.
