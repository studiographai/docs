## Overview

An **entity** is a single node in your knowledge graph — a person, project, meeting, decision, or any other typed record. Each entity is a Markdown file with YAML frontmatter, stored at `{folder}/{entityType}/{entityId}.md`.

## Anatomy

```markdown
---
entity_type: person
entity_id: jane-smith
name: Jane Smith
organization: "[[acme-corp]]"
role: "[[senior-designer]]"
status: current
email: jane@acme.com
tags:
  - design
  - leadership
created_at: 2026-03-01T00:00:00Z
updated_at: 2026-03-15T12:00:00Z
created_by: admin
updated_by: admin
---

Jane leads the design team at Acme Corp. She's currently working on
the [[website-redesign]] project.
```

## Base fields

Every entity has these fields, defined in `EntityBaseSchema`:

| Field | Type | Description |
|---|---|---|
| `entity_type` | string | The entity type identifier (required) |
| `entity_id` | string | Unique kebab-case ID (required) |
| `name` | string | Human-readable display name |
| `date` | ISO date | Optional canonical date for the entity |
| `tags` | string[] | Categorization tags |
| `created_at` | ISO 8601 | Creation timestamp |
| `updated_at` | ISO 8601 | Last update timestamp |
| `created_by` | string | Creator user ID |
| `updated_by` | string | Last updater user ID |

Entity-level visibility is **not** part of the model — visibility is enforced at the [folder](/concepts/folders) level via `folder_access` grants.

## Entity IDs

IDs are kebab-case (`jane-smith`, `dec-2026-001`), derived from the filename, and unique within a folder. Decision IDs follow the convention `dec-YYYY-NNN`.

## Wikilinks

Use `[[entity-id]]` to link to other entities, or `[[entity-id|Display Text]]` for custom display text. Wikilinks resolve across folders and work in both frontmatter and body content. The `find_related` and `validate_wikilinks` tools traverse and check these connections.

When the caller can't access a target folder, cross-folder wikilinks pointing into it are stripped from API responses.

## Status enums

Each entity type defines its own status values. The current set:

| Type | Statuses |
|---|---|
| `person` | current, former, contractor, client, partner |
| `organization` | active, inactive, prospect, former |
| `role` | active, deprecated |
| `project` | planning, scoping, active, on-hold, completed, archived |
| `task` | open, in-progress, done, cancelled |
| `decision` | proposed, accepted, rejected, deprecated, superseded |
| `document` | draft, sent, accepted, rejected, negotiating, signed, completed, terminated |
| `deal` | scoping, proposal, negotiating, won, lost (`stage` field) |
| `deliverable` | planned, in-progress, delivered, accepted, rejected |
| `publication` | draft, review, scheduled, published |
| `deck` | draft, review, final, archived |

## Special entity bodies

Most entities use freeform Markdown bodies with optional templated headings (`## Summary`, `## Action Items`, etc.). Two types use the body for structured payloads:

- **`dataset`** — body is raw CSV. Frontmatter declares column definitions (`name`, `type` of `string`/`number`/`boolean`/`date`, `required`). Parsed and validated on demand by `CSVService`. Agent tools `query_dataset` and `append_rows` read and write rows.
- **`skill`** — body is the prompt content the agent loads on demand. Frontmatter carries `description` and `loading: eager | on-demand`. Skills can be exposed to external MCP clients via `list_skills` / `get_skill`.

## Custom fields and schema extensions

All entity schemas use Zod's `.passthrough()` — custom fields beyond the canonical schema are preserved on read and write. To enforce a custom field, declare it in `workspace.json` under `schema_extensions`:

```json
{
  "schema_extensions": {
    "person": {
      "additional_fields": {
        "github_handle": { "type": "string" }
      }
    },
    "case-study-v2": {
      "fields": {
        "client": { "type": "string", "required": true },
        "metrics": { "type": "string" }
      }
    }
  }
}
```

Both forms compose with `EntityBaseSchema` and are injected into the agent's system prompt.
